## Patterns

- **Engine owns rules.** `applyMove` / `applyTurn` are the only state transitions. Scenes render `afterPlacement` + `waves` and never re-simulate explosions.
- **AI is a wrapper.** `chooseAiMove` scores legal `applyTurn` results. It must not write cells itself.
- **The AI derives from the rule primitives.** `src/game/ai/evaluate.ts` values a position per owned cell with `pressure = count / threshold(cell)` (how close to detonating) and `reach = blastTargets(cell).length`, plus `isNearCritical(cell)` — never from `neighbors`/`diagonals`/`deep` and never from a degree constant, so the same count on a deep cell is worth less because the rule says it fires later. **The guard is eslint-enforced in two scopes:** non-test source repo-wide may not read `.neighbors`/`.diagonals` — the one home, `src/game/engine/board.ts`, and `**/*.test.ts` are exempt — and `src/game/ai/**` may not read `.deep` either, because `.deep` is a display flag the view legitimately reads. So a spread change reaches the AI through the primitives, and a re-derivation of the geometry cannot land outside its one home.
- **One idea, one implementation — a tripwire enforces it.** `src/architecture/no-duplicate-implementations.test.ts` parses every function-like body under `src/**` (test files included), normalizes it (formatting and comments dropped, every identifier blanked, literals reduced to their value), hashes it, and requires every 2+-site population at or above an 80-character normalized floor to equal the checked-in `KNOWN_DUPLICATES` inventory exactly. A new copy fails naming every site (`file:line#name`) with the instruction to fold it; a folded copy leaves a STALE entry that fails until its line is deleted. **The inventory is DELETE-ONLY: an entry is removed when its copies are folded, never added to bless a new duplicate.** The detector's own scope is checked by `SCOPE_FLOOR` and by `KIND_FLOOR` (per syntax form) and printed as `[dup-tripwire] …` on every run: adding bodies is free, losing files/bodies/compared bodies or a whole syntax form is not. It is a TRIPWIRE, not a proof: paraphrases and sub-floor bodies are invisible, and blanking identifiers erases a difference carried only by a name.
- **Campaign is a wrapper.** Missions pick map + difficulty + star thresholds. Progress is Zod-parsed `localStorage` (`loadProgress` throws on junk; the title may reset via `loadProgressOrReset`).
- **Maps are graphs.** `#` is a cell, `*` is a deep cell, `=` is a single-hit wall plate, `+` is an ARMORED plate (two detonations: the first cracks it, the second drops it), `.` is void. **There is no HOUSING glyph any more: EVERY plate that falls reveals an eater, so "which plate reveals one" is the RULE, not a map fact** (the old `@` now throws as an unknown glyph). **`diagonals` is populated for EVERY cell; whether a cell USES them is the `deep` flag**, and `threshold`/`blastTargets` are the gate — a plain cell HAS diagonal neighbours, it just does not count or fire into them. Isolation is the cell's OWN out-degree (`threshold(cell) === 0`), never a raw neighbour count: a plain cell whose only neighbour is diagonal has no firing edge and is still rejected. A plate (`=` or `+` alike) is legal if it touches a live cell orthogonally, or a deep cell diagonally. Durability is authored, never mutated: `MapDefinition.armored` is the `+` subset of `walls`, and `Board.armored` carries it immutably, so "is this plate armored?" is always a map fact.
- **Ownership has THREE states, and neutral is a state, not a missing player.** `Owner = PlayerId | 'neutral'`; `CellState.owner: Owner | null`, and the invariant is one-directional — `count > 0` implies a non-null owner, never `owner: null` with tokens. `neutral` means a token nobody owns. The consequences are structural, not special cases: `legalMoves` tests `owner === null || owner === player`, so a neutral pile is **INERT TO PLACEMENT** (you cannot place into it) with no extra rule; `occupiedCount`/`tokenCount` filter by player, so it is nobody's territory. Two rules govern how it dies: **an owned blast CLEARS it** (a receiver is re-coloured to the spreader with +1, so blasting a neutral pile means INHERITING it), and **a neutral pile that reaches its own natural threshold fires NEUTRAL** — the wave colour comes from the pile, not from the mover. Where a player colour is needed, the type is narrowed at ONE home: `theme.ownerLook(owner)` (and `fx.coreTexture`/`glowTexture`/`flyToken` take an `Owner`), so `theme.player` stays keyed by `PlayerId` and a neutral pile never indexes the player table.
- **One explode rule: threshold is out-degree.** A cell detonates at `threshold(cell)` and dumps exactly one token into every `blastTargets(cell)`. A deep cell is not a second rule — it just fires into the diagonals too, so it counts diagonals toward its threshold: `deepDegree(cell)` = ortho + diagonal degree, `deepBlastTargets(cell)` = those cells. **Threshold must always equal outgoing edges or the cascade would create tokens from nothing and never terminate.** `threshold`, `blastTargets`, `isCritical`, and `isNearCritical` are the only places that know this; never re-derive it from `neighbors.length` outside `src/game/engine/board.ts` (eslint errors on it in non-test source; the one home and `**/*.test.ts` are exempt). A blast that reaches diagonally WITHOUT coming from a deep cell (the eater's detonation) passes `collapseWalls`'s third argument, which names the squares whose blast reaches the diagonals.
- **One wave, one place.** `src/game/engine/cascade.ts` holds `stepCascade`: snapshot the critical piles, `detonate` them, `collapseWalls`, `revealEaters`. The mover's cascade (`move.ts`) and any neutral settle run that SAME step, so a second cascade implementation cannot drift from the first. `detonate` derives each token's colour from the PILE it came from (`neutral` keeps neutral, everything else spreads the mover's, which is why an opponent's pile that fires on your turn hands you its tokens), and neutral tokens land first: where an owned and a neutral token reach one square in one wave, the blaster takes it. **A wipe is the mover's own cascade**: it is awarded only after a wave the mover's colour carried, so a neutral flood that empties the opponent's squares wins nothing for anybody.
- **The eater is an ACTOR, not a wall tweak — and it reuses the one wave step.** EVERY plate that FALLS reveals an eater on the square it fell to, mastered by the player whose turn it is; a plate that only CRACKS reveals nothing, so breaking one is a real, plannable choice. The rule is uniform, so no board fact records which plates are special (the `@` glyph, `MapDefinition.housing`, `Board.housing` and the reveal gate that consulted them are all GONE). `Board.eaters` holds `{ at, master }` in REVEAL ORDER and its HOARD is the `count` of the square it stands on (one home: moving it is a conserved transfer, and its death leaves the surplus behind). Its square is `owner: 'neutral'` EVEN AT 0 tokens, so nothing can be placed into it, and `criticalCells` SKIPS it — it fires by the eater's own rule at `deepDegree(square)`, whether or not the square is `deep`, so a corner pays 3 and the middle pays 8. Each activation it moves to the ORTHO neighbour with the most tokens (clockwise from north, first in a tie wins), absorbs that whole stack, stays if nothing beside it has tokens, and then detonates ONCE if the hoard has reached the deep degree: subtract the deep degree, send one NEUTRAL token per deep target, leave the surplus as neutral, and remove it. Another eater's square is a BODY, never a meal. The phase runs right after the REVEALER's own cascade (`master` is the player whose turn revealed it, and the phase is part of that turn), in reveal order, and a reveal DURING the phase is appended and actuates in the same phase. Its detonation is a deep blast for the wall rule, which is what `collapseWalls`'s third argument says. And the phase is where the board can go all-neutral: if no square is owned by either player afterwards the game is a DRAW, and a wipe is never awarded there — a neutral flood is denial, not capture.
- **Every wave names its own colour.** `WaveStep.spreader` is the colour the wave spreads with (`neutral` when ANY pile in it was neutral) and `TokenTransfer.owner` is the colour of each token, so the scene never paints a neutral flood in the mover's seat colour; `eaterDetonation` marks the one-shot blast that needs its own FX. The hover preview carries `eaterMoves` from the SAME `applyMove` simulation as the dumps — where each eater will eat next, how big the bite is, and whether the bite is its last — so the actor is predictable before the player commits.
- **Plates have durability, and it is one more piece of board state.** A `Board` holds `walls` (INTACT plates — 1-hit and 2-hit alike), `cracked` (armored plates that took their first hit) and `armored` (the immutable map fact); `walls` and `cracked` are DISJOINT, and a cracked plate is STILL A PLATE — same blocking, same `mapBounds`, same rendering, not a `cells` entry. Anything that must see every standing plate reads `boardPlates(board)` (= `walls` + `cracked`), never `board.walls`, and the durability predicates have one home too (`isArmoredPlate` / `isCrackedPlate`), so no scene re-derives them. **Damage is ONE per wave**: a plate touched orthogonally AND by a deep diagonal, or by several exploded cells, is hit exactly once, so a 2-hit plate can never fall to a single wave. `collapseWalls` reports both outcomes as `{ board, collapsed, cracked }` (`collapsed` = fell, `cracked` = newly damaged), and `WaveStep.cracked` carries the crack so the scene flinches the plate (`BoardView.damageWalls`) instead of shattering it (`crackWalls`); the hover preview's `cracked` list draws a hollow ghost, `collapsed` the filled one.
 - **Waves are simultaneous.** Snapshot every critical cell, subtract its threshold, then apply all outgoing tokens. Leftover stays. After the dump, every plate orthogonally beside an exploded cell — or diagonally beside an exploded **deep blast** (a deep cell, or a square the caller names as one) — takes ONE damage: a `=` (or an already cracked `+`) FALLS — it becomes a plain cell, the graph is rewired, and it is then the square of a NEW EATER (`owner: 'neutral'` even at 0 tokens) — while an intact `+` only cracks, reveals nothing, and changes no cell and no edge (`deep` is map-authored, so a fallen plate is always a plain cell). The blast that opens a door does not travel through it.
- **Any new board state enters `hashBoard`.** The position signature is `${cells}|#w:${walls}|#x:${cracked}|#a:${armored}|#e:${eaters}`. Every term is load-bearing for the cascade's repeat guard: adding a field to `Board` without adding it here makes two different positions hash identically, and the guard stops a cascade on a board that is still changing. `#e` lists the eaters in REVEAL ORDER, because that order decides their activations, so it is state and not a set. **TRAP: a term that GROWS without bound (a counter, an append-only log) makes the signature new on every wave, so the repeat guard never fires and a cascade that should settle never terminates.** The eaters' hoard needs no term of its own: it IS the count of the square they stand on, which `cells` already hashes — and storing it twice would be a second source of truth.
- **Painted world, procedural board.** Backgrounds live in `public/assets` and load through `publicAsset()` so subdirectory deploys (`/BlasterMaster/`) resolve. Cells, cores, and HUD are Phaser graphics/text so they can tween.
- **SFX are files, bus is the owner.** Clips live in `public/assets/sfx` (Sound Studio WAVs). `src/game/audio/bank.ts` is the catalog; `bus.ts` decodes and plays them. Title melody loops from the same bank after the first gesture. Do not add a second audio path or a synth fallback.
- **Juice is presentation-only.** Gem cores, orbit, shockwaves, and flights live in `src/scenes/play/fx.ts` + `BoardView`. They decorate engine snapshots and never invent a wave.
- **Layout is testable.** Cell positions come from `src/game/view/layout.ts`, not from ad-hoc scene math. Menu grids use `cardGrid`, which reproduces the plain `firstX + col * pitchX` grid for full rows and centers a short last row — so a tenth map card fits in a fourth column, an eleventh starts a third row that still clears the BACK button, and the twelfth fills that row at x=1105 (`layout.test.ts` pins all three).
- **Reach is drawn, not described.** Each gauge pip sits on the edge it fires through (cardinals for plain cells, plus the corners for deep cells), so pip count is the threshold and pip position is the reach. `reachPips(cell, size)` in `src/game/view/layout.ts` is the pure, tested source of those positions; `BoardView` only draws them and rebuilds them when a fallen plate rewires a cell's edges. Deep cells also carry cut corners in `theme.colors.deep`, a marker that survives every owner/hover/near-critical hue. `previewPlacement` reads engine transfers, so the hover preview shows diagonal dumps for free.
- **Hover flood is `applyMove`.** `previewPlacement` asks the engine what the first wave would do, including first-wave wall falls. The scene never invents dumps, leftover, or collapses.
- **Deploy is subdirectory Vite.** `BLASTER_MASTER_BASE` is the Vite `base`, and its default is `/` (a ROOT build) — the subpath `/BlasterMaster/` must be passed explicitly, which is why `npm run publish` does it for you. This line said the default was `/BlasterMaster/` until 2026-09-27; that was wrong and it is the trap the publish script refuses. `deploy-sync.ps1` builds, patches `RewriteBase`, syncs `dist/`, uploads `/shots/BlasterMaster.png`, and registers the Futuremagic manifesto. Do not store the FTP password in the repo.
- **Publishing is its own step, and it is NOT the push.** `npm run publish` (`scripts/publish.sh`) builds with the project's own subpath base (`BLASTER_MASTER_BASE=/BlasterMaster/`), REFUSES a root-base build (which renders blank under the subpath), rsyncs build output into `~/apps/BlasterMaster/` — a symlink into another root, resolved and printed before writing — and verifies by CONTENT: the served entry must name the asset that was just built, byte for byte. A static host answers `200` for a stale copy as happily as for a fresh one, so `git push` never means the site is live. Measured 2026-09-27: the owner reported a missing tenth map in the published version while `origin/main` already had it.

## Anti-patterns

- **No `any`** — use unknown + Zod / type guards at boundaries
- **No duplicate helpers** — search `src/lib` and `src/game` before inventing; `src/architecture/no-duplicate-implementations.test.ts` fails on any new 2+-site population, so FOLD the copy into its canonical home rather than re-typing it (the inventory is delete-only)
- Do not reverse dependency direction (lib must not import scenes)
- Do not explode cells inside a scene; only play engine wave events
- Do not re-derive the rule geometry outside `src/game/engine/board.ts` — read `threshold`/`blastTargets`/`isCritical`/`isNearCritical`. `eslint.config.js` errors on `.neighbors`/`.diagonals` in non-test source (the one home and `**/*.test.ts` are exempt) and on `.deep` inside `src/game/ai/**`
- Do not put readable text in generated images — composite copy in Phaser
- Do not write a second cascade: a player's waves, a neutral settle and an eater's detonation all go through `cascade.stepCascade` + `board.detonate`, so a rule change cannot leave one of them behind. Do not let state GROW inside anything the repeat guard watches
- Do not add portals, shields, splash radius, or a second explode rule — walls are pending cells, not a new physics. Deep cells pass this bar: same rule, wider out-degree. Armored plates pass it too: same collapse rule, a map-authored hit-point count. A cell that fires into more directions than it counts would break token conservation.
- Do not load `public/` files with a root-absolute `/assets/...` URL — that breaks subdirectory hosting
